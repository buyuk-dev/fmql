Task **0015 — Pseudo-fields `a._id` / `a._path` in Cypher `WHERE`** finalized.

Branch: `feature/cypher-pseudo-fields-id-path`. Plan: `~/.claude/plans/get-started-on-task-curious-hartmanis.md`.

## Outcome

- New `PSEUDO_FIELDS = ("_id", "_path")` constant and `pseudo_field()` helper in `packages/fmql/src/fmql/cypher/expr.py`. `packet_field()` checks pseudo-fields **before** frontmatter, so they are not shadowable — unlike the existing `path`/`filename`/`slug` virtuals.
- `_id` aliases `_path` (workspace-relative POSIX path, equal to `Packet.id`). Rationale recorded in ADR `0003-pseudo-field-id-aliases-path.md`.
- Pseudo-fields override frontmatter even if the user has a `_path:` key — recorded in ADR `0004-pseudo-fields-bypass-frontmatter-shadowing.md`.
- `SET t._path = …` and `REMOVE t._id` are rejected at validation time via a new `_reject_pseudo_write()` helper in `executor.py`. Clear `CypherError` with the message `cannot {SET|REMOVE} pseudo-field {var}.{field}: pseudo-fields are read-only`.
- `_sort_bindings.extract` updated so ORDER BY on pseudo-fields resolves through `packet_field()`.
- Five new tests in `packages/fmql/tests/test_cypher_set.py`: positive WHERE filtering by `_path` and `_id`, non-shadowing assertion, SET rejection, REMOVE rejection.
- README "Virtual properties" subsection extended with a pseudo-fields table, example, and read-only note.
- Code-review pass (`/simplify`): replaced a duplicated literal in `pseudo_field()` with `PSEUDO_FIELDS` (single source of truth); dropped a WHAT-level comment on the constant (the ADR documents the WHY); extracted `_reject_pseudo_write(op, var, field)` to dedupe SET/REMOVE rejection branches.
- Workflow housekeeping: archived prior STATUS body to `docs/changelog/0001.md`; flipped task 0015 to `done`; updated `docs/roadmap.md`.

## Notes

- The grammar required no changes: `IDENT.1: /[A-Za-z_][A-Za-z0-9_]*/` already accepts `_id`/`_path`.
- `PSEUDO_FIELDS` is a tuple, not a hardcoded literal, so adding `_filename`/`_slug` later is a one-line change. Out of scope for 0015.
- The `_validate()` rejection prevents Cypher `SET`/`REMOVE` from ever creating a frontmatter `_path:` key, but it cannot prevent direct YAML edits. Documented in ADR 0004 as the intentional trade-off.
